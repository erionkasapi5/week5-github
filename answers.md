\# Week 5 – GitHub Answers



\*\*1. What is the difference between git commit and git push?\*\*



Git commit saves changes locally in the repository. Git push uploads those commits to the remote repository on GitHub so they are available online.



\*\*2. What does origin mean in Git?\*\*



Origin is the default name Git gives to the remote repository from which the project was cloned. It allows us to refer to the GitHub repository without writing its full address every time.



\*\*3. How many complete copies of your project history exist now, and where are they?\*\*



There are two complete copies of my project history. One is stored locally on my computer, and the other is stored online on GitHub. Both contain the commits and project history that have been pushed.

Developers, users and contributors read a README. It should explain what the project does, what files it contains, how to install or run it, and how people can use it.



\*\*2. What can other people legally do with your code if there is no license?\*\*



Without a license, other people generally cannot legally copy, modify, distribute or use my code beyond what copyright law allows. They must ask the copyright owner for permission.

\# Pull Requests and Git Fetch/Pull



\*\*1. What is a pull request, and why do teams use them instead of pushing directly to main?\*\*



A pull request is a request to merge changes from one branch into another branch. Teams use pull requests because they allow other developers to review the code, suggest improvements and find mistakes before changes are added to the main branch.



\*\*2. What did git pull do in step 5? How is it different from git fetch?\*\*



Git pull downloads changes from the remote repository and integrates them into my current local branch. Git fetch only downloads the changes and updates the remote-tracking branches without automatically merging them into my current branch.
